# デザインドキュメント: OpenCode 権限設定の極限緩和

- **作成日**: 2026-03-27
- **ステータス**: 承認済み
- **対象ファイル**: `opencode/opencode.jsonc`

## 1. 目的
OpenCode エージェントの自律性と作業スピードを最大化するため、現在の「デフォルト確認（ask）」ポリシーから「デフォルト許可（allow）」ポリシーへと移行し、極限まで権限を緩和する。ただし、致命的な破壊操作（`rm`等）や、ファイル指定を伴わない一括 Git 追加（`git add .`）は制限を維持する。

## 2. 背景・制約
- **現状**: 多くの操作で `ask` が発生し、ユーザーの介入頻度が高い。
- **制約**: `rm` はゴミ箱に入らないため禁止を維持する。`git add .` も意図しないファイルのステージングを防ぐため、明示的なファイル指定を強制する。

## 3. アプローチ
- `bash` のデフォルトポリシーを `allow` に変更し、明示的に禁止/確認が必要なものだけをリストアップする「ブラックリスト方式」を強化する。
- 外部アクセス（Web取得、外部ディレクトリ）を無条件許可にする。

## 4. 詳細設計（設定変更内容）

### 4.1 基本ツールと外部アクセス
- `webfetch`: `allow`
- `external_directory`: `allow`

### 4.2 Bashコマンド実行 (`bash`)
- **デフォルトポリシー**: `"*": "allow"`
- **「確認（ask）」を維持・設定**:
    - `git push*`
    - `git reset*`
    - `npm publish*` (deny から緩和)
- **「禁止（deny）」を維持**:
    - `git add .` (ファイル指定を必須とするため)
    - `rm *`, `rm -rf *`
    - `ssh *`, `sudo *`, `su *`

## 5. 検証プラン
1. `opencode/opencode.jsonc` の更新。
2. `omo-set-profile` コマンド等を使用して設定を反映。
3. 実際に許可されたコマンド（例: `git commit`）を実行し、確認ダイアログが出ないことを確認する。
4. 禁止されたコマンド（例: `git add .`）を実行し、正しく拒否されることを確認する。
